# Changelog

This changelog lists changes made in CrossDink. CrossDink started from CrossInk v1.6.0 and keeps merging CrossInk's development branch; for CrossInk's releases and the changes merged from it, see [CrossInk's changelog](https://github.com/uxjulia/CrossInk/blob/development/CHANGELOG.md).

## [Unreleased]

### Added
- X4 Pro (debug builds): remote command `BOOTSLOT` (USB serial `CMD:BOOTSLOT`, Wi-Fi `POST /api/cmd`, token required) shows the other OTA slot's build; `BOOTSLOT <label>` runs the same full image check as Goodies > Boot previous firmware, then switches and restarts into it, so a slot switch needs no USB.
- X4 Pro (debug builds): remote command `MACRO <script.txt>` runs a device test script from the SD card with the Goodies Wi-Fi remote off, then writes results (one line per step with its time and log offset), the PSRAM log and any screenshots next to the script and turns the remote back on. Scripts use the remote commands plus `WAIT`, `MARK`, `WAITLOG` (wait for a log line) and `SHOT`, and carry on across `SLEEPREBOOT`/`REBOOT` steps.
- X4 Pro (debug builds): `GET /api/psram-log/stream` (Wi-Fi remote token) sends the PSRAM log live as it is written, on one open connection, instead of polling `/api/psram-log`. Other requests are served meanwhile, and it adds no wakes: idle, new text goes out within the server's 250 ms idle tick (Goodies > Knobs serverIdlePollMs). Up to 2 streams at once (a third replaces the oldest).
- Goodies Wi-Fi remote: a key, touch, swipe or type command over Wi-Fi briefly drives the frontlight to 50%, whether it is lit or off, then restores your exact level (off stays off), so you can see the input landed. Goodies > Knobs `remoteBlinkMs` sets the length (15 ms; 0 = off) and `remoteBlinkPct` the brightness. Input is never delayed.
- X4 Pro (debug builds): Goodies > Boot previous firmware switches the boot slot to the other OTA slot and reboots. Its confirmation names the slot and that image's project, version, build date and time, and ELF hash prefix; with no valid image there, the row shows "none" and a tap says so.

- X4 Pro (debug builds): power counters for working out what each function costs in battery, since the gauge reports only charge. Time awake, in light sleep and at full clock, per-core busy time, time in each Wi-Fi state, Wi-Fi scans, connects and IP packets, frontlight time weighted by PWM duty, panel busy and booster time, and SD traffic are counted across deep sleep, along with deep sleep split by whether the charger-status wake is armed. A row of these with the battery %, voltage and temperatures goes to `/debug/logs/power.csv` at every wake and sleep, % change, Wi-Fi on/off and every 10 min awake (Goodies > Knobs powerTickMin). Goodies > Power Test runs one load at a time for 30 min (Knobs powerTestMin): idle, frontlight 50% or 100%, Wi-Fi in modem sleep or awake, one busy core, or a Fast or Full refresh loop, marking the log and showing the drop and rate; its voltage sag probe steps each load on and off for about 2 min and logs the cell voltage drop under each. `scripts/power_fit.py` splits the logged drain into a cost per function (%/h, or mA with `--capacity-mah`) and summarizes the Power Test runs. Knobs chargeWake 0 turns off the charger-status wake to compare deep sleep drain with and without it. See docs/power-counters.md.
- Wi-Fi remote (debug builds): `POST /api/image` shows a picture sent from a computer until the next touch or button, which closes it without acting on the screen below. The computer does the conversion (the `xink-image` tool takes any image, fits it to the screen in 4 grays, optional dithering), so the device only draws it: one gray refresh, then the panel is powered off and the device idles in light sleep. See docs/serial-remote.md.
- File Transfer and the Wi-Fi remote: interrupted transfers can resume. Downloads (`/download`, `/api/download`, WebDAV `GET`) honor a single `Range` span with `206 Partial Content` (`416` when it is past the end), so `curl -C -` and download managers pick up where they stopped. `/upload` and `/api/upload` take `offset=<bytes>`: the data goes to `<name>.part`, renamed to `<name>` when done; a dropped upload keeps the part for 10 minutes so the rest can be sent with `offset` set to its size (a wrong offset gets `409 Offset mismatch: have <bytes>`). Uploads without `offset` work as before. WebDAV `PUT` with `Content-Range` is refused (`400`) instead of saving the partial body as the whole file. See docs/webserver-endpoints.md.
- OPDS: opening the OPDS catalog from Home with more than one server joins your saved Wi-Fi network in the background while the server list is on screen (no Wi-Fi screen, the list draws and takes input as before), so picking a server usually goes straight to the catalog. Backing out to Home turns Wi-Fi off again. Skipped when Wi-Fi is already up, no network is saved, or memory is short; a slow or failed join falls back to the Wi-Fi screen as before. Once the link is up, the list also fetches the servers' main pages in the background (up to three at once, as the catalog preloads its pages) and marks a server with the check in the row's left margin (as the catalog marks cached pages; the text does not move) once its page is in (the list redraws once, when the fetches are done); picking a marked server shows its catalog from that copy at once.
- Debug builds with a touch screen: an `[IN] touch noise: N wakes, 0 gestures, C contacts in Xs` line when the touch panel raises at least 10 interrupts a second for 5 s or more without a tap, swipe, long press, Home key or two-finger gesture, as a charging phone next to the screen does (at most one line a minute). Log only: touch input is not ignored or changed.
- Debug builds (X4 Pro): the first deep sleep of each build writes the whole PSRAM log (up to 512 KB) to `/debug/sleep-<sha8>.log` (sha8 = the build's commit; the build's commit id is now 8 characters in the Settings footer and `/api/status` too), since deep sleep wipes the ring. A build whose file exists logs nothing; later sleeps add one SD file check, and the first one delays power-down by the time to write the file, after the sleep screen is drawn. Lines logged after the SD card is shut down (display sleep) are not in it. Goodies > Sleep-reboot-log runs the same sleep path but restarts at the end instead of powering down (a restart keeps the PSRAM log), and saves the whole log, sleep path and the boot after it, to `/debug/sleep-reboot-<sha8>.log` (replaced each run) 15 s after boot; it does not dump at sleep time.
- Debug builds log the web server task's free stack after each download (`[WEB] download done`).
- X4 Pro: Text Anti-Aliasing works in Night Mode (EPUB and TXT text pages). Noflash keeps the black background and white text still and only turns the thin edge pixels dark gray, the negative of the light-mode look; Sharpflash flashes once per page with the vendor's own gray waveform (the black background turns light for about half a second from the start of the refresh, which clears the previous page; a mirrored waveform left ghosts). Image pages in Night Mode stay black and white as before. Noflash's grays are a mirror of the light-mode waveform, not a vendor-calibrated set. Dim Light on Flash has its own timing for Night Mode Sharpflash pages (debug builds: Goodies > Knobs flashGrayDarkDimMs and flashGrayDarkRestoreMs, defaults 0 and -300 ms, the same as light-mode pages).
- X4 Pro image viewer: a picture is decoded once instead of three times (both gray layers and the black-and-white copy come from one decode), BMP rows are read and dithered on the second core while the first draws them, a BMP of up to 4 MB of pixels is read from the SD card in one go, and the last 4 pictures stay decoded in PSRAM while the viewer is open, so going back to one skips decoding. The log line `Decoded once in N ms` gives the decode time.
- Settings > Display > Image Viewer: Same as reader (default), BW dark, BW, Dither or Gray for pictures opened from the file browser (web settings: `imageViewerMode` 0-4). Same as reader follows Settings > Reader > Images (BW dark, BW, Dither; Gray for Display, Placeholder and Suppress). BW dark turns every non-white shade black, BW the darker half of the tones black with no dot pattern, Dither error-diffuses the picture in black and white, and both show it in one fast refresh with no gray pass. Gray is the previous look. PNGs now get the same gray pass as BMPs in Gray (before, the viewer showed them in black and white only); Dither on a PNG uses its ordered dither.
- Debug builds (X4 Pro): `GET /api/download` and `POST /api/upload` copy files off and onto the SD card over the Wi-Fi remote (also in File Transfer), behind the same token and lockout as `/api/cmd`. They are File Transfer's download and upload, so the same paths are protected and an existing file is never overwritten. See docs/serial-remote.md.
- X4 Pro and other PSRAM devices: screenshots taken while an anti-aliased page or gray image is on screen keep its 4 gray levels. The shortcut and reader-menu screenshot saves a 4-bit BMP; the debug `/api/screenshot` returns a PGM. After a black-and-white refresh they are 1-bit as before.
- Settings > Reader > Images (and the reader's pull-up panel, Layout > Images) has four display choices: Display: BW dark, Display: BW, Display: Dither and Display: Gray (the default, the previous Display), then Placeholder and Suppress (web settings: `imageRendering` 4 / 3 / 5 / 0 / 1 / 2). BW dark, BW and Dither show book images in black and white with no gray pass, so image pages refresh like plain text pages; text anti-aliasing still applies to their text. BW dark turns every non-white shade black, BW only the darker half, and Dither error-diffuses the image (the same look as cover thumbnails). Switching between them keeps the book's layout and image caches. With Text Anti-Aliasing on, pages with BW dark, BW or Dither images keep their black-and-white images and only add gray to the text, and a page with only images skips the anti-aliasing pass.
- KOReader Sync > Auto Sync: Disabled (default) / At open / At close / Both, below Manual Sync Behavior (the renamed Sync Behavior, which now applies only to syncs you start; also in the web settings as `koAutoSync` 0-3; a saved Sync on Book Exit becomes At close). Auto Sync always works like Smart Sync and runs in the background, with no screen and nothing to wait for. At close pushes the book's saved position when it closes and never moves the server back: it first fetches the server's position (both document hashes) and pushes only when the server has none or the device is further on, for any forward move; otherwise the push is skipped and logged (`exit push skipped: ...`), without turning Wi-Fi on when the book is not past the server position last seen. A "Progress uploaded!" toast shows for a moment when a push lands. At open fetches the remote position a moment after the book opens (never pushes); when the remote is further on, a popup ("Apply remote progress", with the remote's percent and device) asks before the page changes, and Cancel keeps your page. A sync's requests share one secure connection, and once a book's record is found under one document hash, later syncs of that book until the next restart or sleep ask for that hash only. It needs sync credentials and a saved Wi-Fi network: Wi-Fi comes on for the sync and goes off again (an existing connection, the Wi-Fi remote's included, is used and left up; while the Wi-Fi remote is still joining, a sync waits up to 20 s for it). A sync starts 1.5 s after the book closes or a book opens (a push waits while a Wi-Fi screen is up, and still runs if you open another book); a close push still pending when the device goes to sleep is finished first, under a "Syncing progress..." toast, capped at 30 s. It is skipped when internal memory is below 64 KB free or a 20 KB block (debug builds: Goodies > Knobs koSyncMinFree, koSyncMinBlock). Failures only go to the log (`exit push ...`, `open pull ...`, with the heap at start, after the join and at the end).
- KOReader Sync > Sync on Wake & Sleep (default off; web settings `koSyncSleepWake`): sleeping from an EPUB saves its position and pushes it before the sleep screen, under a "Syncing progress..." toast, then shows the result ("Progress uploaded!", "Already synced", "Server is further on, kept" or "Sync failed") for 1.5 s before the sleep screen draws (the same never-move-back check applies; the whole wait is capped at 30 s, so sleep always goes on, and a power press during it is not a wake). It follows Auto Sync: the sleep push needs At close (or Both), and the wake's reopen of the book fetches with the At open popup only when Auto Sync has At open, as any open does; after a failed sleep push, that wake also pushes.
- X4 Pro: Settings > System > Device > Turbo Keyboard (on by default for new settings; a saved setting keeps its value). Typing redraws the keyboard with a short charge-balanced quick refresh (6 frames per phase; debug builds: Goodies > Knobs kbdFrames), keys tapped while the screen is still updating appear together in the next update, and the key you tapped shows light gray in the same refresh that prints it, until the next key. The keyboard opens, and the screen below redraws when it closes, with the panel's stock fast refresh.
- OPDS: choosing a book asks "Download? <title>" with its size before downloading (from the feed when it says, otherwise looked up in the background; "?" if unknown). A book already on the SD card gets the overwrite question with its size and date instead, and no size lookup.
- OPDS: background page loads give up after 10 s of silence instead of 60 s, pause 30 s after a network failure, and a page loaded in the last minute is not rechecked when you go back to it, so Wi-Fi can idle sooner while browsing.
- Debug builds (X4 Pro): Goodies > Knobs lists internal timing, threshold and frame-count constants on tabs like Settings (Panel, Light, Touch, Power, Heap, Book, Wi-Fi; long-press Up/Down or tap to switch) with their units, and changes each one with a slider; changed rows show a *. Changes apply at once and are saved to `/.crossdink/knobs.json` (only values that differ from the default); Reset all goes back to the defaults and deletes the file. If the device crashes 3 times without staying up 30 s, the file is set aside as `knobs.bad.json` and the defaults are used; holding Back while it starts ignores the file for that boot. Memory gates can only be raised. Also over USB serial and the Wi-Fi remote: `KNOB list [from]`, `KNOB changed [from]` (only the knobs off their default, as `id=value/default`), `KNOB get <id>`, `KNOB set <id> <value>`, `KNOB reset [<id>]`. Display frame counts only feed the charge-balanced waveform generators; waveform shapes, voltages and VCOM are not knobs. Release builds keep the constants and are unchanged.
- Debug builds (X4 Pro): Goodies > Keyboard test, for trying typing feel and speed. Type opens the on-screen keyboard on a scratch field (kept while Goodies is open, never saved). Below it, - and + buttons set Turbo keyboard and the keyboard knobs (kbdFrames, kbdHighlightDelayMs, kbdTouchHoldMs, kbdTouchDelHoldMs, contactJumpPx, tapSlopPx; Left/Right on button devices). Changes apply at once, Turbo from the next keyboard open; nothing is written to the SD card while the page is open; it is written after you leave it (by the time Goodies closes), or before sleep, restart or a firmware flash.
- X4 Pro (debug builds): the battery log also records charging starting and stopping while the device sleeps. The charger's status line wakes the device for a moment (no screen, SD card or panel activity; at most 16 times per sleep) and the rows (`chg_on`, `charged`, `chg_off`, detail `asleep`) are written at the next wake. Power-button presses too short to wake the device (when the short press is not set to wake it) are counted as false wakes: the next wake row adds `false_wakes=N awake_ms=M`, and Goodies > Battery & stats and the web page show the total.
- Web portal: a Logs page (nav link on every page) shows `/api/status`, the PSRAM log (debug builds) and every file under `/debug/` on the SD card (battery logs, crash report, display scripts). Pick a source to view it, type to filter its lines, or download it. Sources a build or card lacks are left out.
- Web portal (X4 Pro debug builds): a Battery page (`/battery`, with its own nav link; old `/logs#battery` links still open it) built from the battery log (all four files plus rows not yet written to the card; `battery.csv` and the unwritten rows show first, the older files are added as they load): % over time with asleep, on-USB, Wi-Fi and lost-power bands and boot, firmware and transfer markers; voltage and battery temperature graphs (same plot width, so their time axes line up); hover for any row; 1 h to all-time ranges (1, 2, 3, 6, 24 h, 3 and 7 days, all). Tables give the same counters as Goodies > Battery & stats, counted from the log the same way (from the last `stats_reset` row), drain and estimated runtime by state (asleep, awake, Wi-Fi, light), every discharge session (awake and asleep drain) and every charge session (speed, time to full). `/api/status` adds those counters under `battery.stats`, and `/api/battery-pending` serves the unwritten rows. A Rows parsed line gives the rows read from each battery log file and from the unwritten buffer ("of N lines" when some lines were skipped).
- X4 Pro (debug builds): battery log. Battery % changes, charger connect/disconnect and charge complete, boot (with reset reason), deep sleep and wake, firmware updates, Wi-Fi on/off, File Transfer/Calibre/USB Drive start and end, and frontlight level changes each add a row (time, %, mV, charging, USB, battery temperature, light level) to a 64 KB buffer in PSRAM that survives restarts and crashes. It is written to `/debug/logs/battery.csv` on the SD card before every sleep, soon after a restart or crash (not after a wake from sleep), when the buffer is 3/4 full or (with the battery at 5% or less) 4 KB is waiting, always after 2 s without input; at 256 KB the file becomes `/debug/logs/battery.1.csv`, which moves on to `battery.2.csv` and `battery.3.csv` (1 MB in all, about 4 weeks of heavy use or months of reading). Every row reads voltage and temperature (at most 5 s old); a USB or charging change is logged once it has held for 5 s, `charged` only when charging stops at 95% or more with the cable in, and a sleep or restart with Wi-Fi on logs `wifi_off`. Light rows come from your own light changes and Light Timeout, not from Dim Light on Flash or the transfer pulse, and show your level. A row written before the battery gauge first answers after a boot leaves the % blank.
- X4 Pro (debug builds): Goodies > Battery & stats shows a battery % graph from that log (a bar marks time awake), the battery % with 2 decimals (from the gauge's fractional charge), "Chg: A% to B% over 1h 21m, 7m ago" (the last charge session, start to unplug, its length and how long since; USB dropping out for under a minute counts as one session; "Charging from A% (now B%)" while plugged in), drain per hour awake and per day asleep over the whole battery log (time on USB left out), and Est to empty, the time to empty at the awake drain logged for the current Wi-Fi and frontlight state (e.g. "18h (Wi-Fi on, light 30%)"). The light's share is scaled by the LED power the current brightness draws rather than its % (brightness follows a perceptual curve, so 1% is 1/1023 of full power, 10% is 23/1023 and 50% about a third; warmth doesn't change it), only ever adds drain, and is capped at the LED's full-light drain (Goodies > Knobs ledMaxDrain). Recent use weighs more: an awake step's weight halves for every day it is older than the newest step in its state (Knobs batteryHalfLifeH, 0 = equal weights). With one light side missing the estimate uses the other side's awake rate, with too little data for the state it falls back to the whole log, and it follows brightness and Wi-Fi changes made while the page is open. Drain rates use the gauge's fractional readings and leave out the first 30 min after a charge (the gauge keeps rising for about 25 min after unplugging; after a charge that ends at 95% or more they wait for the first 0.05% drop) and the first 2 min after a light, Wi-Fi or wake change (Knobs batteryStateSkipS). Each shows rate ± error, where the ± counts the gauge's wander (±0.25% per stretch, added in quadrature, so it shrinks as the log grows), and reads "not enough data" until the log holds a 0.2% drop (per-state rates need 30 min and 0.5%). The page also shows how long ago the earliest log row is (durations read 12m, 1h 21m, 2d 3h), wake/false wake/cold boot/restart counts, awake and asleep time, refresh counts by kind since power-on, temperatures (CPU: the ESP32-S3's internal sensor; panel), uptime, reset and wake reasons and the firmware sha. It opens at once with "calculating..." and fills these in as the log is read in the background; the counters, drain and last charged come from all four log files. The page saves its counts in `/debug/logs/battery.sum` after a read of over 32 KB, so later opens read only the rows added since and the counts keep the rows of log files rotated out since. The web Battery page starts from the same saved counts (`/api/battery-sum`) and counts on from the rows after them, so both match. Reset (OK, or the header button on touch) asks first, then adds a `stats_reset` row: counting starts again there and the log file keeps everything. Refresh (Right, or the header button left of Reset on touch) re-reads the log and the live readings. Lines that don't fit scroll with Up/Down or a swipe.
- X4 Pro (debug builds): Goodies > Battery & stats and the web Battery section show light sleep since boot: how many light sleeps, the share of uptime spent in them, rejected attempts and the cause of the last rejection (e.g. "LS 1234 (78% of 2h 10m)  Rej 56, last GPIO"; refresh counts read "Ref: Fa 12  Ha 3  Fu 1  Gr 4  Fl 0" (fast, half, full, gray passes, flashing)). Updated every 30 s and on each screen change; `/api/status` has them under `battery.stats.lightSleep`.
- X4 Pro (debug builds): Goodies > Display test > Panel conditioning. After a confirm, about 30 s of balanced black/white swings with null discharges in between, ending on white, to even out charge left on the panel. Back stops it between swings.
- X4 Pro: Display > Frontlight > Dim Light on Flash (off by default). Whenever a refresh flashes the screen (Half/Full, anti-aliased pages in Sharpflash, full-screen scrubs; not menus, the drawer or Noflash page turns over an anti-aliased page, which only change the text edges), a lit frontlight fades out just as the flash shows and fades back up to your level over 0.3 s when the refresh ends. The display driver times it for each waveform, so on anti-aliased pages the light stays up for the first half of the refresh, before the background moves. Flash Dim Level (0-90% in 10% steps, default 0% = dark) sets how far it dims, as a share of your brightness. Each kind of refresh has its own timing, set from its waveform: on anti-aliased page turns the light is dark as the background goes black and starts back up once the page stops going dark, 0.3 s before the refresh ends; on Half/Full refreshes and full-screen scrubs it is dark from 0.4 s in and starts back up 0.8 s before the refresh ends. Debug builds tune each kind in Goodies > Knobs: flashGray/Full/Paint DimMs and RestoreMs (-800 to +800 ms, negative is earlier; the dim never starts before the refresh does) take effect on the next flash, and flashDimLevel there is the same Flash Dim Level setting; neither ever delays a refresh. It never turns on a light that was off and saves nothing to the SD card. It never dims the light below 2% of full (lower levels shift its color) and does nothing when your brightness is already 2% or less; debug builds can raise that floor in Goodies > Knobs flashDuckMinPct (up to 20% of full). A brightness slide during a dim fades up to the new level when the flash ends.
- X4 Pro: Text Anti-Aliasing has three choices: Off, Sharpflash (one full-screen flash per anti-aliased page, the previous behavior) and Noflash (no full-screen flash on text pages: the page shows in black and white first, then only its light-gray edge pixels turn gray, for bolder text; slower; image pages, the first page after opening a book and the first page after a menu refresh like Sharpflash). Noflash keeps unchanged black and white pixels (the status bar, the background) from fading with a short balanced re-drive at the end of each turn, and every Refresh Frequency pages it runs one full gray refresh (one flash). The in-reader menu offers the same three choices; picking one closes it and the page redraws once in the new mode. Other devices treat Noflash like Sharpflash.
- X4 Pro: Display > Frontlight > Light Timeout (1 / 2 / 5 / 10 min / Never, default Never). With no input for that long, the frontlight fades out over 1 s. The next key or touch brings it back at once and still does what it normally does, so the first tap after the light dims is not lost. It never turns on a light that was off, and it waits while File Transfer, Calibre or USB Drive keep the device awake; after a transfer light pulse it counts from the end of the pulse.

Join Network in File Transfer uses the remote's connection, and turning the remote off shuts Wi-Fi down in the background.

### Changed
- Tapping a list row that opens a choice popup (Settings, Image Viewer, Home, OPDS servers, bookmarks and the like) now draws the highlighted row and the popup in one e-ink refresh instead of two, so the popup shows about 0.6 s sooner.
- Tapping a list row that opens a confirmation or book-actions popup (Goodies, Library, File Browser, Saved items, Settings and the like) now also inks the highlighted row and the popup in one refresh, so it shows about 0.6 s sooner. A tap that opens one of these over a page with no list (reader, image viewer) no longer redraws the page first.

- Debug builds (X4 Pro): the 2 s `[MEM] Periodic`, `[CPU]` and `[PERF]` log lines are now one `[SYS]` line (`heap ... psram ... sd ... img ... core0 X% core1 Y% over N ms act=<Activity> | <tasks>`). Each part prints only when it has news and leaves out what carries none: the constant heap/PSRAM totals (still in `[MEM] Boot`), PSRAM min/maxAlloc unless they changed, zero SD/image counters and tasks under 10% of a core. On a recent 43-minute log these lines took 45% less of the PSRAM log ring, so a dump reaches further back. A cached book section rebuilt after a reader setting change now logs `[INF] [SCT] Section cache params changed, rebuilding` instead of an `[ERR]`, and any main-loop pass of 200 ms or more logs `[LOOP] Slow loop: ...` (at most one line per 5 s), not only a new maximum.
- Logs: the SDK's own lines (display probe `[XTDET]`, SD card mount failures `[SD]`, `[MEM]`, firmware flash `[FLASH]`) now go through the app log like every other line: they carry the timestamp and level, reach the PSRAM log (`/api/psram-log`, debug builds) and no longer cut into a screenshot or log dump over USB serial. OPDS debug lines follow the build's log level, so release builds no longer print them.
- Logs: a new `[WRN]` level (shown at the same log levels as `[INF]`, amber on the web Logs page, not counted as an error) for expected conditions: a Wi-Fi remote bad token, a cancelled download (now `Transfer cancelled`) and a recent book removed from the card. Debug builds (X4 Pro) also put ESP-IDF's own lines (`E (1234) wifi: ...`) in the PSRAM log, and `/debug/crash_report.txt` adds the last 16 KB of the PSRAM log after a crash; the RTC copy of the last log lines shrinks to 4 lines of 128 bytes there. Log calls are checked against their format strings at compile time (`-Wformat`), and 424 mismatched arguments (mostly `%u` with `uint32_t`) now use `PRIu32` or `%lu`.
- CrossDink keeps its data in `/.crossdink` instead of `/.crosspoint`. Settings, Wi-Fi, recents, bookmarks, clippings, stats, OPDS, KOReader, knobs, library and sleep-image indexes, and XTC/TXT reading progress are read from `/.crosspoint` until CrossDink first saves them, which writes them to `/.crossdink`; `/.crosspoint` is left untouched, so CrossInk and older builds still find their data. EPUB caches are now named by the book's content instead of its path, so moving or renaming a book (also from a computer or over USB) keeps its progress, settings and stats; its progress, reader settings and stats are copied from `/.crosspoint` the first time the book is opened. Caches, covers and thumbnails are never read from `/.crosspoint`; they are rebuilt. Each cache folder has a `path.txt` naming its book. Settings now live in `/.crossdink/settings.json`, imported once from `/.crosspoint/crossink-settings.json`, else `/.crosspoint/settings.json`. A re-uploaded or edited book whose content changed keeps its progress and reading stats (the Library index remembers each book's key).
- Library scan ("Reading your books"): a card with no changes is checked against the saved index without writing anything to the SD card (before, every cold boot wrote and deleted a ~1 KB staging record per book). On PSRAM devices the saved index is read into memory once per scan and a rebuild keeps its staging records in memory, so only the new index is written. After a card change, the Library opens at once with the previous list and rescans in the background (paused while you use it), and the rows update when it finishes; book actions and Refresh still rescan right away. Cover Grid Home no longer rescans behind a popup on every boot and wake. A book's content key (its cache name) is read in 4 KB chunks, once per changed book per scan instead of three times, and the Library grid reads progress through the key in the index. Debug logs add a `counters:` line per scan (index reads, staging bytes, tail reads, walk time per book).
- Debug builds (X4 Pro) log more about slow spots: one `[ERS] open:` line per book open with the time of each stage (key, legacy copy, metadata or indexing, image index, section, first page) plus the rest and the total; an `[SDW]` write, rename, remove or mkdir over 100 ms adds its time, and a slow write splits it into open, close and lock wait and says whether it created the file; long `[SDW]` paths keep their start and file name and drop the middle; the legacy cache copy line gives files, bytes and ms; `[PM]` splits timer wakes into esp_timer alarms and task ticks and a second line names the three busiest esp_timers; boot marks name the wake check, IMU probe and RTC read. The last 8 screens opened and the last error line are kept in RTC memory (192 B, kept through deep sleep and restarts, cleared on power loss) and printed at the next boot as `[BOOT] trail:`, since the PSRAM log does not survive deep sleep.
- Fewer SD card writes and waits while browsing and reading: the Library, Home and the sleep screen no longer write a book's progress percent file when it is missing (the reader still saves it on exit); a Library grid page with missing cover thumbnails repaints once when they are all ready instead of once per thumbnail; optimized book images are unpacked straight into their cache file in 4 KB pieces instead of being copied twice in 256-byte pieces; each book's ZIP directory is read once into PSRAM, so opening a chapter or image no longer scans it (10-25 ms each before); the optimized-images manifest is parsed in PSRAM instead of through a temporary file; and a book with no per-book dictionary choice is no longer checked on the card twice every time the reader's pull-up panel opens.
- Snappier screens: settings changed on a screen are saved while the next screen refreshes instead of before it draws, and `settings.json` is rewritten in place (with a `.bak` copy written first, which a damaged file falls back to) instead of through a new temporary file that took about 0.6 s to create; Library grid cover thumbnails are made on the second core, so the Library takes taps while they are made; the reader's pull-up panel looks for dictionaries once per reading session instead of on every open; Home no longer draws its first frame twice after a silent restart. Debug logs: a redraw that no input caused is no longer billed as a slow tap.
- X4 Pro: a book image shown for the first time is decoded from a copy in PSRAM instead of a raw copy written to the SD card first (up to a few MB per image), which also takes the SD write out of its first view (about 0.8 s for a 1 MB image). The small decoded cache is still saved. With PSRAM short, it falls back to the SD copy. The log line `Background decode ... src=psram` shows which was used.
- Lyra Carousel theme: coming back to Home from a book rewrites its saved Home picture (48 KB per recent book) only when something it shows changed (progress %, reading time to the minute, whether stats exist), not after every reading session.
- The automatic reading-stats backup (on by default) is written once a day, at the first sleep of the day, instead of being refreshed at every sleep after reading. It lags the live stats by up to a day; a manual backup still writes a fresh copy at once.
- Saving `state.json`, Wi-Fi credentials, the remote token and `koreader.json` overwrites the file instead of deleting and recreating it, one SD card directory change fewer per save.
- Waking into a book no longer writes `state.json` to the SD card (2-3 writes per wake before): the reader's crash guard (which sends the next boot to Home after a book crashes while opening) is kept in RTC memory, and a save that changes nothing is skipped from the first boot on.
- Reading stats (per book and overall) are saved in place, alternating between two copies with a checksum (like reading progress), so leaving a book or sleeping from it costs 2 SD card writes for stats instead of 8; if a save is cut off by a crash or power loss, the previous save is used. `stats_v5.bin.bak` is now the second copy, not a leftover. Overall stats move to `global_stats_dink.bin` (and its `.bak`); the old `global_stats.bin` is read until the first save and then left as is, so older firmware still shows the overall stats as of the update instead of empty ones.

- SSD1677 panels: anti-aliased text no longer pushes gray pixels one way on every AA page. The AA gray pass now drives each gray level both ways (about 21 frames instead of 12, no extra flash), and the firmware refuses to build if any SSD1677 waveform is DC-unbalanced.
- X4 Pro: the display no longer uses one-way (DC-unbalanced) drives, which built up charge and made screens dirtier over time and risked lasting image retention. Every refresh now uses the panel's own waveforms: screen entries and File Transfer / OPDS / Calibre / Nearby / OTA / font download / SD firmware progress repaints are OTP Fast, and reader ghost cleanups are the balanced Half (a short flash at your refresh-frequency setting). Headers on long transfer screens may fade slightly.
- X4 Pro: the first time a page with a large image (such as a book's cover) opens, the image is unpacked and decoded in the background. The page shows its image frame at once and fills it in when ready; buttons, swipes and menus keep working meanwhile instead of freezing for several seconds.
- After a KOReader Sync or Nearby sync, later Wi-Fi sessions in the same boot no longer run with Wi-Fi power saving off.
- KOReader sync: pressing power or letting the device sleep during a slow sync no longer freezes it for up to ~16 seconds; it waits at most 3 seconds, then sleeps.
- Debug builds: serial file downloads and CMD:PSRAMLOG dumps no longer lose bytes when the USB buffer is full, and a log line can no longer land inside a serial reply or binary stream. A reply to a host that has closed the port no longer stalls the device for half a second. Blank lines and xink-remote's ">>>>> " echo lines are ignored quietly.
- Check for update now looks at CrossDink's own GitHub releases instead of upstream CrossInk's, so an upstream release can no longer be offered and flashed over CrossDink. It only accepts a release firmware for this device (`firmware-<device>-v<version>.bin`).
- X4 Pro: touch, the battery gauge and the clock share one I2C bus, and a battery or clock read from another task could overwrite a touch reading mid-copy (phantom taps, odd battery or temperature values). Each I2C transaction now holds the bus until its data is copied out, and the clock's cached time can no longer be read half-updated.
- OPDS: book downloads run in the background, so Back and the Cancel button stop them at any point (the partial file is deleted) and the screen shows Connecting until the first byte arrives. Downloads also start sooner: the free-space check no longer scans the whole SD card first.
- X4 Pro: joining Wi-Fi is about 1.5 s faster. The address conflict check that was meant to be off was still running on every join.
- A chapter left half-indexed by an older firmware is re-indexed instead of resuming with outdated page positions.
- Saving the reading position before opening Wi-Fi, Calibre, KOReader sign-in, file transfer or the light panel waits for the screen to finish drawing, so it can no longer read or close a chapter that is still being indexed.
- On the X4 Pro and Sticky, the Home screen no longer stalls waiting for the SD card while the Library indexes in the background.
- Small images that are scaled up, such as a short progressive JPEG, are now cached after the first draw instead of being decoded again on every screen refresh.
- The serial log no longer reports errors for normal events: a missing image, section or dictionary cache file on first open, an outdated section cache being rebuilt, and a device without a clock chip or motion sensor. Log lines that were missing a line break now end cleanly, and SD, display, TLS and frontlight messages use the standard log format.
- KOReader authentication now rejects unexpectedly large server responses to avoid crashes.
- KOReader Auto Sync: closing a book (or sleeping) on a page before the one you opened it at no longer pushes that earlier position; paging back to look something up leaves the server where it was.
- File Transfer (Wi-Fi mode): the Wi-Fi signal bars no longer show twice; only the header status bar draws them.
- File Transfer and WebDAV: a connection that opens but sends nothing (a spare one GNOME Files/gvfs or Finder keeps ready) no longer holds up every other request for 5 s. Once another connection is waiting, the silent one is closed after 1 s. Debug logs: `Closing silent connection fd N, another is waiting`.
