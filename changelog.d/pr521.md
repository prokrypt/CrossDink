Goodies (debug builds): **Flash bootloader** writes `/bootloader.bin` from the SD card over the second-stage bootloader after checking the image (ESP32-S3 header, appended SHA-256, QE set for a quad bootloader, bootloader accepts this app); the old bootloader is restored if the write does not read back. CI builds that bootloader (`tools/bootloader`: QIO, OTA rollback, no app image check on power-on wakes) as the `bootloader-x4-pro` artifact. Boot logs `[BOOT] flash cache io=` (the cache read mode the bootloader set), `idf bootloader app check=` and `bootloader idf=.. built=.. QE=` (the bootloader's own version stamp and the flash chip's Quad Enable bit). X4 Pro: the firmware is built for Quad I/O (QIO) flash. The app enables the flash chip's quad mode and reads flash over four data lines; the cache that runs code stays in dual mode until the bootloader is reflashed over USB once, after which code and font reads from flash move four bits per clock instead of two.
